# =============================================================================
# Endpoints treated as GraphQL.
#
# A POST to a destination listed here has its body parsed to decide whether it is a query
# or another operation:
#   query                 -> follows read-allowlist.txt (or write-allowlist.txt)
#   mutation/subscription -> conservatively follows write-allowlist.txt
# A body that cannot be interpreted is denied.
#
# Ordinary GitHub GraphQL queries and mutations are POSTs to the same endpoint, so reads and
# writes cannot be told apart without looking at the body. GitHub's introspection GET is an
# ordinary read and does not need body classification. A POST to a destination that is not
# on this list is evaluated normally against write-allowlist.txt alone, without inspecting
# the body.
#
# **Why this is not detected automatically**: a guess such as "it is GraphQL if the JSON
# has a query key" would misread a write to a non-GraphQL REST API as a query and let it
# through on the read allowlist alone. A false positive directly undermines safety, so this
# applies only to explicitly listed destinations.
#
# The format is the same as the read/write allowlists (domain + optional, case-sensitive
# path pattern).
# As in write-allowlist, "*" (every domain) is not allowed here: if every destination
# were treated as GraphQL, a POST to any domain would pass on the read allowlist alone
# simply by carrying a body shaped like a query (reads default to "*"). Using it causes
# startup to abort with an error.
# =============================================================================
