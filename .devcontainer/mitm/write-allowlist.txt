# =============================================================================
# Destinations allowed for write methods (POST/PUT/OPTIONS/PATCH/DELETE).
#
# Reads (GET/HEAD) are managed separately by read-allowlist.txt. Domains that only need
# read access (downloads, CDNs, etc.) belong there, not here.
#
# Format: one entry per line, either "domain" or "domain<whitespace>path-pattern".
# Everything after # is a comment.
#   .example.com               leading dot = matches subdomains and the apex / every path
#   example.com                no dot = exact match (subdomains are not included)
#   .example.com  /api/*       prefix match; only paths starting with /api/
#   .example.com  */callback   suffix match; only paths ending with /callback
#   .example.com  /graphql     exact match
# Paths are matched case-sensitively with the query string removed. * is allowed once, at
# the start or end.
# Unlike read-allowlist.txt, "*" (every domain) is not permitted here; it is an error at
# startup.
#
# Writing "*.example.com" / "https://example.com" / "example.com/path" in the domain field
# aborts startup with an error (previously such lines were accepted and silently became
# entries that never match).
# Note that requests whose path has a "." or ".." segment, contains "%2e", or has a "%2f"
# that decodes into a dot segment are denied with unsafe_path, whether or not a path is
# specified.
#
# This file is bind-mounted into the mitm container, so after editing it no rebuild is
# needed: `restart mitm` is enough (edit it on the host).
# If something is denied, run `docker logs devcontainer-mitm-1 | grep DENIED` to find the
# destination and reason. Add it here only for an intended write denied with default_deny;
# unsafe paths/ports, Host mismatches, WebSockets, and unsupported methods need other fixes.
# =============================================================================

# ----- GitHub is allowed only on the paths that are needed -----
# This write allowlist permits authentication (the device flow and token retrieval) and git
# fetch. Read-only GraphQL queries are separately permitted through read-allowlist.txt and
# graphql-endpoints.txt.
# Do not remove the path patterns: writing ".github.com" by itself would allow ordinary
# write methods used by git push and PR creation.
# Keep */git-receive-pack (git push) and REST/GraphQL writes denied.
# /login/* applies to github.com (the apex) only. With a leading dot it would also cover
# api.github.com, letting POSTs to API paths unrelated to authentication through without
# any body inspection.
github.com  /login/*
.github.com  */git-upload-pack
